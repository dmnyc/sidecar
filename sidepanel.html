Client tag

Add a “client” tag to notes and page comments you post, attributing them to Sidecar. Turn off to post without it.

Background app syncs

Clients quietly sync app settings (read status, preferences) as you browse. These aren’t posts, so Sidecar handles them without interrupting you when a site uses more than one of your accounts. Turn on to confirm each one instead.

Global name search

The first time you search a Nostr name, Sidecar offers to also ask a third-party index (api.nostrarchives.com) that covers every user, and to send it the people you follow so it can fill in names your relays missed. That service then sees both what you type and who you follow — which nothing else reveals together. This switch is that answer; @mentions from your own relays keep working either way.

Covers zaps you start in a client. For other payments, give a site its own daily budget under Sites.

Bootstrap relays

Used to discover your relay list on first load, and as a fallback if it can't be reached. Once you've published a relay list from the Profile tab, these take a back seat.

NIP-65 only is set per account. When it's on for an account, these relays are excluded from its reads and publishes — except the initial discovery fetch, which still queries them once per session to find that account's relay list. Sites calling getRelays() still see the bootstrap set regardless.

A ws:// relay is unencrypted — fine for a local or Tor relay, but anything on the open internet should be wss://.

Auto-lock

Sidecar asks for your PIN once per browser session even on Never — your key is held in memory and never written to disk unencrypted.

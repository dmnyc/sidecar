Sidecar comment lab

NIP-22 comments used as replies to a note. Every case signs a kind:1111 with a throwaway key and publishes it, so the thing to watch is Sidecar's bell, not this page.

Press Refresh in the bell. The live subscription only runs while the panel is open, so a comment published while it was shut is not missing, it just has not been asked for. The refresh icon in the sheet's corner is what asks.

1. A comment directly on the note

Root and parent are the same, so you are in p as well as P. Expect "replied to your note", with the same glyph a kind:1 reply gets. This shape always arrived: it is the control.

2. A reply to that comment

p is the first commenter by now. You are named only in P. Expect "replied to your note". This is the one that was invisible: a #p filter cannot match P, so everything below the first level of a thread on your own note was silently missing.

3. A comment that omits P entirely

Some clients do. Only the root E names you at all. Expect "replied to your note". This is why the filter is anchored on #E against your own notes rather than on #P: an uppercase filter would miss exactly these.

4. A mention inside someone else's thread

Rooted on a note the throwaway key posts itself, merely p-tagging you. Expect "mentioned you in a comment", NOT "replied to your note". The promotion to a reply has to be about whose thread it is, not merely about being tagged in a 1111.

5. A page comment

The original use of this kind, scoped to a URL with I/K rather than to an event. Expect "mentioned you in a comment", unchanged.
